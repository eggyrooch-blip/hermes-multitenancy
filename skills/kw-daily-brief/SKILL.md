# KippiesWork 每日行业早报

按订阅者的岗位（`role`）生成过去 24 小时的行业简报。

**这个技能零授权依赖** —— 不读飞书、不读内部系统，只做 web search。任何员工订阅后立刻可用。

## 参数

调用方（通常是 cron 订阅）在 prompt 里给出：

- `role` — 必填，取值见下方岗位清单
- `extra_focus` — 可选，订阅者补充的关注方向（自由文本）

未给 `role` 时**不要猜**，直接输出一句「请告诉我你的岗位（法务/财务/产品/市场/HR/技术），我才能给你对的早报」并结束。

## 岗位清单与搜索方向

### role=法务

1. 广告法/互联网广告合规：《广告法》《互联网广告管理办法》修订、市场监管总局广告监管新规、虚假宣传典型案例
2. 最高法/最高检动态：司法解释、指导性案例、典型案例
3. 民事诉讼/仲裁：民诉法、仲裁法司法解释或实施细则
4. 综合立法：全国人大、国务院法规发布或征求意见稿
5. 即将生效提醒：未来 30 天内生效的重要法规

搜索词组（每组至少一次）：
- `广告法 {当前年份} 新规 OR 修订 OR 案例`
- `最高人民法院 司法解释 {当前年份}`
- `市场监管总局 广告 {当前年份}`
- `全国人大 立法 {当前年份} 最新`
- `即将生效 法律法规 {当前年份}`

## 工作流程

1. **先确认今天的日期** —— 用 terminal 执行 `date '+%Y-%m-%d %A'`。不要凭记忆推断日期，`{当前年份}` `{当前月份}` 都从这里取。
2. **按岗位执行搜索**，每个词组至少一次。若 `extra_focus` 有值，额外补一组针对它的搜索。
3. **逐条核验**：每条入选信息必须有可访问的来源 URL，且发布时间在最近 24 小时内。拿不准发布时间的，用 web_fetch 打开确认。
4. **按输出格式组织**，推送到当前会话（`target: origin`）。

## 输出格式

```
# 📋 {岗位}早报 · {今日日期}

## 🔴 {板块一}
（每条：标题 / 发布机构 / 发布日期 / 核心内容一句话 / 对本岗位的影响提示 / 来源链接）

## ⚖️ {板块二}
...

## ⏰ 近期生效提醒
（未来 30 天内即将生效的重要规定；无则写"暂无"）

## 💡 今日关注建议
（1-2 条针对本岗位的重点建议）
```

板块按岗位清单里的方向拆，没有内容的板块标注「暂无更新」，**不要删掉板块**（订阅者靠板块位置快速扫读）。

## 反编造规则（硬性）

这是订阅制推送，订阅者不会去核对，所以宁可少给也不能编：

- **每一条都必须有真实可访问的 URL。** 没有链接的信息**一律不写**。
- **URL 必须是这一条本身的出处，不是"同一个站点上另一篇文章"。**
  这是最容易犯且最难被发现的错：搜索结果里有 A、B 两篇，你写了 A 的内容却挂了 B 的链接，
  读者点进去看到的是另一回事。判据很简单 —— **链接的标题/slug 必须与你写的这条内容对得上**，
  对不上就是错的。拿不到这一条自己的 URL 时，**删掉这一条**，不要用相近的链接顶替。
- **不确定发布时间的，不写。** 不要把三个月前的旧闻当成"最新动态"。
- **不要从标题推断内容。** 搜索结果的标题常有误导，拿不准就 web_fetch 打开看。
- **确实没有当日新内容时，如实说**：输出「今天这个方向没有新动态」，然后可以补一句近期最重要的动态并**明确标注它的日期**。
  ——「没有」是一个合格的输出，编造不是。
- 条数不足 5 条时**不要凑数**，如实说明搜到几条。

## 成本约定

本技能是全员规模的每日任务，属主要成本项。执行时：

- 搜索次数控制在 8 次以内，够用即止
- 不要对每条结果都 web_fetch，只对**发布时间存疑**或**标题信息不足**的条目打开
- 模型档位由运行时 `auxiliary.<task>.model` 决定，**本技能不指定模型**
